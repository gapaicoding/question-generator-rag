# antislop audit 002, 2026-10-18

Scope: post-redesign re-audit of `app/page.tsx`, `app/layout.tsx`, `app/globals.css`, `DESIGN.md` v2.0, and all of `components/` (including the new `DeleteDocumentDialog.tsx` and `ThemeToggle.tsx`). Also re-scanned `lib/` and `components/` for comment hygiene (antislop-code) and all visible UI copy (antislop-copywriting).

Mode: AFTER (audit existing code, fix only on approval).

## 1. [HIGH, R-25] "Aktif" status chip fails text contrast in light mode

**Rule:** All text must meet WCAG AA 4.5:1 for normal text.

**Finding:** `components/DocumentList.tsx:117-125` renders the active-document chip as `bg-accent-green/15 text-accent-green`. The 15%-opacity green tint blends with the card/hover background differently per theme. Computed against the actual blended backgrounds:

- Dark mode: `#22C987` text on the blended `~#1E4351` background = 4.94:1, passes.
- Light mode: `#15803D` text on the blended `~#CDE1DE` background = **3.68:1, fails** the 4.5:1 normal-text minimum (it only clears the 3.0:1 large-text bar, and this is 12px/`text-xs`).

---

## 2. [MEDIUM, R-32, antislop-human "Broken Tab Order"] Delete dialog has no focus trap

**Rule:** Every interactive element reachable and operable by keyboard, and a dialog's focus should stay contained while it's open.

**Finding:** `components/DeleteDocumentDialog.tsx` focuses the Cancel button on open and closes on Escape, but does not trap Tab/Shift+Tab inside the dialog. A keyboard user can Tab past "Hapus"/"Batal" straight into the page content behind the modal, which is also not marked `aria-hidden`/`inert` while the dialog is open, so screen reader users can navigate into content that's visually and logically supposed to be blocked.

---

## 3. [LOW, Liveliness Block 3 / R-37] No explicit ENERGY/RHYTHM/MOTION dial was declared for the v2.0 redesign

**Rule:** Every design must set the three dials explicitly (a Design Read line before building), per the core's Liveliness Toolkit.

**Finding:** `DESIGN.md` v2.0 (the user-supplied spec this redesign was built from) doesn't state dial values, and no Design Read line was declared before implementing it. This is a process gap, not a quality problem: the actual output already varies section composition and uses motion sparingly (hover/focus transitions only, no loops), which reads roughly as ENERGY 2 / RHYTHM 2 / MOTION 1. Worth recording explicitly so future additions to this UI get calibrated against a stated target instead of drifting by feel.

---

## Follow-up: all 3 approved and fixed (2026-10-18)

1. **R-25 fixed.** Replaced the opacity-blend chip background (`bg-accent-green/15`, whose effective contrast is unpredictable and theme-dependent) with dedicated solid tokens: `--chip-active-bg: #dcfce7` (light) / `#10261e` (dark), paired with the existing `--accent-green` text. Verified by reading the actual computed styles in a live browser: light mode renders `#15803D` on `#DCFCE7` (4.57:1, passes), dark mode `#22C987` on `#10261E` (7.41:1, passes).
2. **R-32 fixed.** `DeleteDocumentDialog.tsx` now renders through a `createPortal` to `document.body`, traps Tab/Shift+Tab inside the dialog (wrapping from the last focusable element back to the first and vice versa), and sets `inert` + `aria-hidden="true"` on `<main>` while open, removing both on close. Verified live: Tab from "Batal" goes to "Hapus" then wraps back to "Batal"; Shift+Tab from "Batal" wraps to "Hapus"; `main` has `inert` while the dialog is open and not after it closes.
3. **Fixed.** Added a "Liveliness dial (implementation addendum)" section to `DESIGN.md` recording ENERGY 2 / RHYTHM 2 / MOTION 1 as the dial actually realized by this implementation, for future additions to calibrate against.

Re-ran `npm run build` after all fixes: compiles clean, no TypeScript errors. All three fixes verified against a live browser (not just read from the code) with zero console errors.

## What was clean

- **Copywriting (antislop-copywriting):** scanned every visible string in the redesigned UI, no em dashes, no buzzwords, no fabricated stats/testimonials, no chatbot closers, no rule-of-three padding. Copy stays specific and utilitarian throughout.
- **Code comments (antislop-code):** only one comment exists across the changed files (`ThemeToggle.tsx`'s `localStorage` catch), and it explains genuinely non-obvious behavior (storage can throw in private browsing), exactly the kind antislop-code says to keep.
- **Theme coverage (R-34):** every other new color combination (FileText/Search icon contrast on raised/hover backgrounds, selected-row border, the "Nonaktif" chip, the green `Cari` button) was checked against the actual contrast script in both themes and passes.
- **State-not-color-only:** selection state carries a text label ("Aktif"/"Nonaktif") plus a border/background treatment, never color alone.
- **aria-live coverage:** upload, document list, search, and generate errors/loading all announce through `aria-live="polite"` regions, matching the spec's accessibility section.
