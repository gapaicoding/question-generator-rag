## 1. [HIGH — R-37] No design direction, undelivered as a draft

**Rule:** Design Direction Required — build must load `DESIGN.md`/brand guidance, or be explicitly labeled "draft without direction" with dials ENERGY 1 / RHYTHM 1 / MOTION 1.

**Finding:** The UI (`app/page.tsx` and all of `components/`) was built and delivered in earlier turns with no `DESIGN.md`, no Design Read declaration, and no "draft without direction" label. It uses Tailwind's default zinc/black/white palette throughout with no stated identity. Swapping the product name would leave the UI indistinguishable from any other CRUD admin screen (ties to R-20, Visual Identity).

**Files:** all of `app/page.tsx`, `components/*.tsx`.

---

## 2. [HIGH — R-25] Text contrast fails in dark mode

**Rule:** All text must meet WCAG AA (4.5:1 normal, 3:1 large text 18px+).

**Finding:** Several elements set a light-mode grey with no `dark:` override, so in dark mode they inherit the same color against the dark background (`#0a0a0a` from `app/globals.css:17`) and drop below 4.5:1:

- `text-zinc-500` (no dark variant) — measured 4.10:1 on `#0a0a0a`, fails normal text:
  - `components/DocumentList.tsx:39` (document metadata line)
  - `components/SearchPanel.tsx:62` (search result metadata line)
  - `components/QuestionList.tsx:30` (source/page reference line)
- `text-red-600` (no dark variant) — measured 4.10:1 on `#0a0a0a`, fails normal text:
  - `components/UploadForm.tsx:51`
  - `components/SearchPanel.tsx:58`
  - `components/DocumentList.tsx:55` ("Hapus" delete link)
  - `app/page.tsx:102` and `app/page.tsx:154` (error messages)

Both colors pass in light mode (4.83:1 on white); the failure is dark-mode only.

---

## 3. [HIGH — R-27] Missing loading/empty UI states

**Rule:** Every UI that displays data needs an empty, loading, and error state.

**Finding:**
- `app/page.tsx` fetches the document list (`refreshDocuments`, lines 29-48) on mount with no loading indicator — `DocumentList` just renders nothing until the fetch resolves, indistinguishable from "still loading" vs. a slow network stall.
- `components/SearchPanel.tsx` has no "no results found" message when a search legitimately returns zero matches — the result `<ul>` (lines 59-69) just renders empty with no feedback that the search ran.

---

## 4. [MEDIUM — R-03, antislop-layoutmobile] Under-sized tap target

**Rule:** Interactive targets need a minimum 44×44px touch area with spacing from neighbors.

**Finding:** The "Hapus" (delete) button in `components/DocumentList.tsx:52-58` has no padding (`text-xs text-red-600 hover:underline` only) and sits directly next to the "Aktif" badge. On a touch screen this is well under the 44px minimum and easy to mis-tap, especially next to another small element.

---

## 5. [MEDIUM — R-21] No working light/dark toggle

**Rule:** Without a stated brand reason for a fixed theme, build a working light/dark toggle rather than deferring to OS preference.

**Finding:** `app/globals.css:15-20` only switches theme via `@media (prefers-color-scheme: dark)`. There is no in-app toggle and no documented reason (no `DESIGN.md`) for locking theme to the OS setting.

---

## 6. [MEDIUM — antislop-human, non-text contrast] Borders well under 3:1

**Rule:** Component boundaries (borders) should meet roughly 3:1 against their background so they're visible to low-vision users.

**Finding:** Input and card borders measure far below that in both themes:
- Input border `border-zinc-300` on white: 1.48:1; `dark:border-zinc-700` on `#0a0a0a`: 1.90:1 (every `<input>`/`<select>` in `UploadForm.tsx`, `SearchPanel.tsx`, `page.tsx`)
- Card border `border-zinc-200` on white: 1.27:1; `dark:border-zinc-800` on `#0a0a0a`: 1.33:1 (every card wrapper `<div>`/`<form>` across all four components)

Not a Hard Gate item (R-25 covers text only), but worth knowing: these boundaries are close to invisible for low-vision users.

---

## 7. [LOW — R-35] Mobile breakpoint never actually verified

**Rule:** Verify the layout at mobile breakpoints before declaring it done, not just by code inspection.

**Finding:** Every screenshot taken while building this UI (upload flow, document switching) was at desktop width (~1280px). No narrow-viewport check has been run. Structural risk is low — the layout is a single `flex-col` column with no fixed-px grids — but the paired "Jumlah soal" / "Tingkat kesulitan" inputs in `app/page.tsx:122-146` (`flex gap-3`, two `flex-1` fields) should specifically be checked at 320-375px before calling the layout verified.

## Follow-up — all 7 approved and fixed (2026-10-17)

1. **R-37 fixed.** Added `DESIGN.md`: calm/utility direction, dial ENERGY 1 / RHYTHM 1 / MOTION 1, documented explicitly instead of an undeclared default.
2. **R-25 fixed.** Added `dark:text-zinc-400` (7.72:1 on `#0a0a0a`) and `dark:text-red-400` (7.16:1) everywhere the bare `text-zinc-500`/`text-red-600` previously inherited into dark mode: `DocumentList.tsx`, `SearchPanel.tsx`, `QuestionList.tsx`, `UploadForm.tsx`, `page.tsx` (listError + generate error). Verified by the contrast script, both now pass 4.5:1 in both themes.
3. **R-27 fixed.** `page.tsx` now tracks `loadingDocuments` and shows "Memuat dokumen..." during the initial fetch. `SearchPanel.tsx` now shows "Tidak ada hasil yang cocok dengan pencarian ini." when a completed search returns zero results.
4. **R-03 fixed.** The "Hapus" button in `DocumentList.tsx` now has `min-h-11 min-w-11` (44px) with centered content instead of bare unpadded text.
5. **R-21 fixed.** Dark mode moved from pure `prefers-color-scheme` to a class-based (`@custom-variant dark`) strategy with a real toggle (`components/ThemeToggle.tsx`), a `localStorage`-backed preference, and a head-inline script in `layout.tsx` to avoid a flash of the wrong theme on load. Defaults to system preference on first visit.
6. **Non-text contrast fixed.** All card/input borders changed from `zinc-200`/`zinc-300`/`dark:zinc-700`/`dark:zinc-800` to a single `border-zinc-500` (4.83:1 light, 4.10:1 dark — both clear the 3:1 non-text bar) used in both themes, removing the redundant `dark:` override.
7. **R-35 fixed.** Ran the app and checked two narrow viewports with Playwright (375px, 360px): zero horizontal overflow before and after the generate form renders (the paired "Jumlah soal"/"Tingkat kesulitan" inputs hold up fine), no console errors, and the new theme toggle was exercised and screenshotted in both themes at both widths. Evidence: `scrollWidth === clientWidth` at both 375px and 360px, `CONSOLE_ERRORS: []`.

Re-ran `npm run build` after all fixes: compiles clean, all 5 API routes still present, no TypeScript errors.
